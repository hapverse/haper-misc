Print page - empty state redesign, orange accent (Android)

Three takes on the owner's sample for the Print documents empty state, plus one fix on the Options screen. Every colour below is an existing token from haper-android/.../ui/theme/Color.kt - nothing invented. Orange = the app's existing amber family (AuthEyebrow / AddButtonDeep #C2691A, the BROWSE label and the Help-pill gradient end; SaveChipInk #A85212 for small orange text). All prices, limits and the minimum shown here are filled from the store's print config at runtime - the numbers in the mockups are today's dev values, not hard-coded copy. Phones are 390 x 844, top 760 px shown.

D - Options screen: show where ₹40 comes fromShip with any variant

The breakdown stopped at the ₹12 top-up, so ₹8 + ₹12 = ₹20 never matched the ₹40 in the bar. Two rows from the quote close the gap: Delivery charge ₹20, then a bold Total ₹40 (= quote.total, never added up on the phone). Purple dashed boxes are annotations only.

Product constraints this design respects

  • Colour printing is not built (decision: black & white only). The sample's "Colour Print ₹5 / page" card cannot be live. Recommendation: hide it (A, B). A "Coming soon" tile (C) is a fake feature. If colour is ever wanted it needs backend work (a colour rate in print config + quote + order validation) and an admin setting - not just a card.
  • Prices come from store config. Big figure = pricePerSideSingle. Second line "Double-sided ₹1.50 / page" = pricePerSideDouble, shown only when it is set and cheaper.
  • Minimum strip reads minimumOrderAmount: "Minimum order ₹20 · about 10 pages" where 10 = round-up(20 / 2). Never a hard-coded "10 pages". Second line from printDeliveryCharge pre-empts the D confusion.
  • Strings: every number and limit (20 MB, 200 pages, A4, rates, minimum, delivery) is filled from the server print config; the sentence wording is app copy.
  • Tap targets: back 44 visual / 48dp touch, consent row 48dp tall, Choose file 54dp, Replace 48dp touch height. Price card and strip are not tappable (info only).

Why A

Hierarchy: the green "Choose file" stays the one obvious next action, exactly as on every other Haper screen. Orange already means "money / offer" in this app (SAVE chips, Offers, add buttons), so using it for the per-page price is consistent, not decorative. One card instead of a fake second card keeps the screen honest. D ships regardless - it is a bug-level clarity fix.
