## What to copy for Haper (design judgement, not from observed evidence)
1. Keep the v2 spec: "N sizes" pill on the card, bottom sheet with one row per size (price, MRP, discount, stock, own ADD/stepper).
2. + on a multi-size card opens the sheet, never adds silently.
3. Cart: one line per size, keyed by the variant id.
4. Detail page: size tiles, price block follows the selected tile.
5. Out-of-stock size: dim the row/tile, show "Out of stock"; "Notify me" only if that feature exists.
6. Data: prefer separate sellable items (own id, stock, price) linked by a shared groupId, plus a default flag. Per-size stock and cart lines then need no new concepts. Also expose a `variants[]` array on the list payload so the card needs no extra call.
7. All new backend fields nullable/defaulted (Android Gson); an item with no variants behaves as single-size.
8. Default size = first in-stock by ascending size; do not pre-highlight in the sheet.
9. Cap per line = min(6, stock); one clear toast at the cap.
10. Have a human compare against the live apps before sign-off.
