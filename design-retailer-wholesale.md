- Reuse everything. Customer colours/type/radius = Color.kt / Type.kt / Theme.kt / Dimens.kt in `/Users/office/Documents/haper/haper-android/app/src/main/java/com/bheldi/ui/theme/`. - Screen shell for status screens = the payment-status shell (icon circle, title, subtitle, glass card, button stack) in `ui/screens/checkout/PaymentStatusScreen.kt`. Form chrome = `HaperScreenHeader`/`HaperTopBar` + `HaperPrimaryButton` + `HaperSecondaryButton`; menu rows = `ProfileMenuItem` in `ui/screens/profile/ProfileScreen.kt`.
- ONE new customer token: `WholesaleInk` = #6B3FA6 (text on `AccentPlumContainer` #EADFF7 = 5.68:1, on white 7.27:1). Marker fill reuses existing `AccentPlumContainer`. Why: wholesale needs its own hue; green = retail brand/in-cart, amber/orange = ADD and SAVE, red = danger, teal = success; plum is the only free hue and already exists for "promo" rows. `AccentPlum` itself (#9A6FD0) is 2.95:1 on its container, so never use it for text; use it only for the 1.5dp marker outline.
- Admin: NO new tokens. Wholesale pill = `--accent-soft` fill + `--accent-text`. (No `--warning`/`--info` besides `--warning-*`; do not hardcode.)
- Status colour map (both apps, always icon + text, never colour alone): PENDING = warning (WarningSurface/WarningText; admin `--warning-*`), APPROVED = success (SurfaceChip/GreenAction; admin `--success`), REJECTED = danger (DangerSurface/DangerDeep; admin `--danger`), SUSPENDED = neutral grey with lock icon (SurfaceMint/InkSecondary; admin `--text-secondary` outline). Suspended is neutral, not red, so it reads "paused by Haper", not "you did something wrong" (reason is shown separately).
- Numbers: Rs with no decimals for whole amounts, 2dp when paise present; Indian grouping (Rs 1,24,000). Dates "17 Nov 2026" (admin "17 Nov 2026" too, matches size-groups A9). Mono (Monospace) for GSTIN, 15 chars grouped for reading only in display: `10 ABCDE1234F 1 Z 5` is NOT used - show unbroken, letter-spacing +0.5sp.

## 2. Apply form
Route: full screen (not a sheet - 8 fields + camera). Header "Become a retailer" with back arrow. Sub-heading under header (InkSecondary 13sp): "Tell us about your shop. We verify every application, usually within 1 working day." (the "1 working day" is an ops promise - needs ops confirmation, see Q4; remove if not confirmed.)
Layout: single column, 16dp side padding (`screenHorizontal`), 16dp between fields, section eyebrows (GreenSubtle uppercase 11sp) "Shop details", "GST details", "Shop address", "Photos". Bottom: sticky CTA bar (SurfaceWhite, hairline top, safe-area aware, `scrollBottomPaddingStickyCta`). Keyboard: bar rides above IME; fields scroll into view.

Fields (label above input, Poppins 13sp SemiBold InkPrimary; input = existing text field: 52dp, radius 18dp (`input`), 1dp BorderHairline, focus 2dp TealPrimary, error 1.5dp DangerDeep + message below in DangerDeep 12sp with leading icon):
1. Shop name (required, max 120). Hint "As shown on your board, e.g. Madhur Kirana Store".
2. Owner name (required, max 120). Prefilled from profile name (editable).
3. Business type (required): single-select chips (Kirana, Medical, Cosmetics, General store, Other). Chip = 40dp, selected = SurfaceChip + 1.5dp GreenPrice + check icon.
4. GSTIN (required). Mono, auto-uppercase, no spaces, maxLength 15, keyboard = ascii/uppercase (not numeric). Validation (client, mirrors server `gstin.utils`): format `^\d{2}[A-Z]{5}\d{4}[A-Z][1-9A-Z]Z[0-9A-Z]$`, mod-36 checksum, state code in known list.
   - While typing (<15): no error; counter "7/15" InkTertiary right-aligned under field.
   - At 15 chars (instant) and on blur: valid -> TealPrimary check + line "Registered in {State name}" (GreenAction 12sp; state derived from first 2 digits - this is a self-check for the user, not a government lookup; copy never says "verified"). Invalid format -> "That doesn't look like a GSTIN. It has 15 characters, e.g. 10ABCDE1234F1Z5." Bad checksum -> "Check the last character - this GSTIN doesn't add up." Unknown state -> "First two digits aren't a valid state code."
   - Submit-time server errors: `GSTIN_TAKEN` -> field error "This GSTIN is already registered. Contact support if it's yours." with a "Contact support" text link (opens existing support screen); `GSTIN_INVALID` -> same as format message.
5. Legal / business name on GST certificate (required, max 120). Hint "Exactly as on your GST certificate - ops match it". (Plan has legalName; label explicitly to prevent PHOTO/NAME_MISMATCH rejections.)
6. Shop address: tappable card (not an input) showing address summary or "Add shop address"; opens the EXISTING address picker/map-pin flow (`ui/screens/address`) in "shop" mode (no label chips Home/Work, no delivery-instructions). Returns summary: line1, area, city, PIN + mini map thumb (MapLand). Must have a confirmed pin (reuse Edit-Address GPS gating). Error: "Add your shop address". Out-of-area is server-side (`OUT_OF_SERVICE_AREA` rejection), not blocked at form.
7. Shop photo (required): 16:9 upload tile (SurfaceSunken, dashed 1.5dp BorderHairline, camera icon, "Add shop photo", sub "Front of the shop with signboard visible"). Tap -> bottom sheet (existing sheet style): "Take photo" / "Choose from gallery". After pick: image fills tile, bottom-right "Retake" pill (SurfaceWhite 92%), x remove. Client downscale to max 1600px long edge, JPEG q80, max 5 MB after; larger/unsupported -> error "Photo is too large or not an image. Try another." Camera permission denied -> sheet shows only gallery + inline "Camera access is off. Allow it in Settings to take a photo." with Settings link.
8. GST certificate (optional): same tile, 96dp tall, accepts image or PDF; shows file name chip (ellipsis middle) + size. Label "GST certificate (optional)" with sub "Speeds up approval".
Consent line above CTA: "By applying you agree to share these details with Haper for verification." (InkSecondary 11.5sp; "Privacy policy" link to existing webview.) Photos are private KYC - a lock icon + "Only Haper's verification team can see your photos." under the photo tiles.
CTA: `HaperPrimaryButton` "Submit application" 52dp. Disabled (SurfaceMint fill, InkTertiary text - existing disabled idiom) until all required fields pass local validation; disabled button is still tappable-announced: tapping a disabled-looking CTA is NOT used - instead the CTA stays ENABLED and on tap scrolls to + focuses the first invalid field and shows all errors (better for a11y than a dead button). Decision: enabled always, validate on tap. Only disabled while submitting.
Submitting: button shows spinner + "Submitting..." , fields read-only; uploads show a 4dp progress bar under the CTA ("Uploading photo 60%"). Back while submitting -> confirm "Cancel upload?".
Success: replace route with Status screen PENDING (3) with a one-time success animation (TealBright check circle, reuse payment-success icon; reduced-motion = static). Toast not needed.
Errors: network -> inline banner above CTA (DangerSurface) "Couldn't submit. Check your connection and try again." + Retry; all inputs kept (state survives rotation/process death via saved state; photo URIs persisted to app cache). 429 `RESUBMIT_LIMIT` -> banner "You've reached the limit of 5 submissions this month. Try again after {date}, or contact support." 409 `ALREADY_APPLIED` -> go to Status screen. 413/415 -> photo tile error. Server 5xx -> same as network + "Our side - try again in a minute".
Offline on open: form usable, fields editable; Submit shows the network banner; no queued submission (KYC uploads are not fire-and-forget).
Dirty back: if any field filled -> dialog "Discard application? What you entered will be lost." [Keep editing] [Discard].
Resubmit (after REJECTED): same form prefilled from `application`, top banner (DangerSurface) "Last time: {reason label}. Fix this and resubmit." ; the field related to the reason code gets an amber outline (GSTIN_* -> GSTIN, PHOTO_UNCLEAR -> photo, NOT_A_SHOP -> photo+name). Photo must be re-added only if reason is PHOTO_UNCLEAR; else existing photo shown as "Already uploaded" tile (can replace). CTA label "Resubmit". Resubmit blocked client-side if nothing changed: CTA tap -> "Change something first - we can only re-review an updated application." `resubmitsLeft` shown as sub text when <= 2: "2 submissions left this month".
Long text / 200% font: labels wrap, never truncate; inputs min 52dp grow; chips wrap to multiple rows; sticky CTA stays one line (text may wrap to 2 lines; bar grows). Address card wraps to 3 lines then ellipsis. File names ellipsize middle.
A11y: every field a labelled TextField (visible label = accessible label); errors via `semantics { error() }` + live region polite; GSTIN announces "G S T I N, 15 characters, 7 entered" on focus only (no per-key spam); photo tile role=Button "Add shop photo, required"; success announces "Application submitted, under review". Touch >= 48dp. Focus order = visual order, top to bottom. Contrast: DangerDeep text on white only (4.6:1); never DangerDeep on DangerSurface for <14sp (3.93:1) - banner text on DangerSurface uses InkPrimary with a DangerDeep icon.
Platform: iOS = same fields, `PhotosPicker` + camera, `.textInputAutocapitalization(.characters)`; web = `<input capture>` + file input, GSTIN `autocapitalize=characters`.

## 4. Wholesale packs in cards, sheet, detail, cart
Extends F1-F4 of the variants spec; only the deltas are listed. A wholesale pack is just another size in the group (<= 8 total sizes; `defaultIId` is always a retail size, so card image/default are retail).

Marker ("Wholesale"): pill 20dp tall, radius full, fill `AccentPlumContainer`, text `WholesaleInk` Poppins 10sp ExtraBold uppercase "WHOLESALE", 12dp storefront icon left. Used on: sheet row (inline after size label), detail tile (top-left tag in place of the "N% OFF" tag position - packs have no discount), detail price block, cart line, order summary. NOT on the product card (card is group-level; it stays unchanged).

Pack label: the admin-set label, recommended "Pack of 100" (Label max 20 chars, validation in 10). Show label verbatim; secondary line "100 pcs" is not repeated if the label already contains the number (use `wholesale.units` only for the per-piece line).

Card (F1): unchanged. Only effect: the "N options" count includes wholesale sizes for retailers. "from Rs X" still = lowest in-stock price among ALL visible sizes? NO - exclude wholesale packs from "from" (a Pack of 100 at Rs 1,150 is higher anyway, but a pack's per-pack price can be lower than 100 singles yet higher than 1 single; it must not drive "from"). Rule: "from" is computed over retail sizes only; if every retail size is out of stock but a pack is in stock, card shows the pack's price with no "from" and the caption "Wholesale only" (WholesaleInk) - card remains tappable.

Sheet rows (F2): wholesale rows are sorted by the admin rank like any other (recommended: after retail sizes). Row content:
- Thumb 56dp (base image) | line 1: label "Pack of 100" Poppins 14sp SemiBold + WHOLESALE pill | line 2: price Quicksand ExtraBold 15sp GreenPrice (per pack), NO struck MRP and NO % OFF unless the pack has `mrp > price` (then show as retail rows do) | line 3: per-piece line "Rs 11.5 per piece" (InkSecondary 10.5sp) - this REPLACES the "Rs X / 100 g" line. Recommendation: hide the per-100 g/ml line for packs (a pack has no weight; computing it is misleading and invites false comparison); the per-piece line is the comparison that matters to a shopkeeper ("is Rs 11.5 per piece less than Rs 14 for one?"). Where the base has a retail price, add a savings hint only if ops enables it (not v1).
- Line 4 (conditional): "Only 2 packs left" (WarningText 11sp SemiBold) when stock <= `lowQty` or <= 5. Derived from `quantity` on the pack row (= floor(base/units)); never show base units. Singular "Only 1 pack left". When 0 -> row sold-out treatment (F2: 55% opacity, "Sold out" DangerDeep, no ADD).
- ADD / stepper: unchanged. Cap = min(stock, 6?) - see Q1; at the stock cap the + dims 40% and tap toasts "Only {N} packs available". Never reuse "Max 6 per order" for packs unless Q1 says so.
- Non-retailer or flag OFF: wholesale rows do not exist in the payload; nothing to hide client-side. The client must NOT filter by itself; render what the server sends.
- A retailer sees a one-time inline hint at the top of the sheet the first time a sheet with a pack opens: "Wholesale packs are only visible to verified retailers." (SurfaceMint strip, x dismiss; stored per install). Optional; drop if it feels noisy.

Detail tiles (F3): pack tile same 108dp footprint: line 1 label ("Pack of 100", wraps to 2 lines allowed; tile height equalises), WHOLESALE tag top-left, line 2 price, line 3 "Rs 11.5 / piece" (replaces Rs/100g), optional "Only N packs left". Selected/in-cart/OOS treatments as F3. Price block under tiles for a pack: price (no MRP unless present), "Rs 11.5 per piece - 100 pieces" line, and a SurfaceMint info row "Wholesale price. No coupons or discounts apply." (InkSecondary 12sp; D6). Sticky bar: left block shows "Pack of 100" + "Inclusive of all taxes" + [new, one extra line] "GST invoice with your GSTIN" (10.5sp InkTertiary).
Initial selected tile stays the retail default; tapping a pack row in the sheet selects the pack tile.

Wholesale rail on Home (plan: `GET /user/retailer/wholesale-items/:page`): optional section for approved retailers only, titled "Wholesale for your shop" (Quicksand sectionHeading + "See all" GreenAction), reusing `ProductRailCard`. Placed after the first category rail. Hidden when API returns 0 items or 403. Skeleton = standard rail skeleton. "See all" opens a standard paginated item grid (reuse aisle grid) titled "Wholesale". This is the discovery surface; sizes in cards remain the main one.

Cart (F4): pack lines look like any size line: name, second line "Pack of 100" (InkTertiary 11sp) + WHOLESALE pill inline, stepper, line total. Under the cart items, when the cart has >=1 wholesale line, a SurfaceMint note (12sp InkSecondary, storefront icon): "Wholesale items don't get coupons or offers. Delivery fee and free-delivery limit work as usual." Coupon row: wholesale-only cart -> existing "not eligible" behaviour with copy "Coupons don't apply to wholesale items"; mixed cart -> coupon applies to retail lines only and the coupon sheet's saving text says "on retail items". Free-gift progress bar counts retail lines only (footnote "wholesale items excluded"). A wholesale line that became unavailable (404 from server) shows the existing unavailable-line treatment with "No longer available".
Bill details: separate lines are NOT split; one total. Order detail & invoice: "GST invoice" button unchanged (backend renders B2B).
Loading/empty/error: reuse existing; empty wholesale rail hidden; stock change while in cart -> existing "Only N left" mechanism, wording "Only N packs left".

## 12.9 Accessibility and motion summary
- Touch targets >= 48dp on switch segments, "Add N", quantity number, nudge, sheet buttons. Admin controls >= 32px (admin density).
